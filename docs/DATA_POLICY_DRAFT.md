# 데이터 처리 방침 (초안 — 제출 전 운영진 검토 필요)

> 목적: 외부 평가 B-7 지점(개인정보 생명주기 무정의)에 대한 최소 정책. 약관이 아니라 엔지니어링 계약으로 기술한다.
> 상태: 초안(2026-09-11). 법률 자문 없이 작성됐다 — 서비스화 시 전문 검토 필수.

## 1. 수집 데이터와 목적

| 데이터 | 저장 위치 | 목적 | 고지 |
|---|---|---|---|
| 이메일 | users.email | 로그인 식별·비밀번호 재설정 | 가입 화면 명시 |
| 닉네임 | users.nickname | 화면 표시 | 가입 화면 명시 |
| 비밀번호 | users.password_hash | 인증 — **페퍼+bcrypt로 저장, 원문 미보관** | 가입 화면 명시 |
| 질문·AI 응답 원문 | chat_logs | 서비스 핵심 기능(기록 조회·문맥 유지) | 본 문서 + 가입 고지 |
| 접속/운영 로그 | stderr 구조화 로그 | 장애 조사·보안 — **대화 원문·시크릿 미포함**(FR-18) | 본 문서 |

**관리자 열람 고지 문구(가입 화면 추가 권장)**:
> "서비스 지원과 오류 조사를 위해 관리자가 귀하의 대화 내용을 열람할 수 있습니다. 열람 시 누가·언제·어떤 기록을·왜 봤는지 감사 로그로 남습니다."

## 2. 보존 기간

| 구분 | 기간 | 근거 |
|---|---|---|
| 대화 기록 | 계정 유지 중 (삭제 요청 시 즉시) | 서비스 목적상 필수 |
| 세션/인증 부산물 | 쿠키 Max-Age(기본 24h)·재설정 토큰 30분 | 이미 구현된 만료 정책 |
| 운영 로그 | stderr 수집기 보존 정책 따름(현재 미수집 — TODO #11) | 수집 도입 시 본 표 갱신 |
| 백업 | 7세대 교체(순환) — 가장 오래된 것부터 자동 소멸 | scripts/backup_db.py |

## 3. 파기

- **회원 탈퇴/관리자 사용자 삭제**: FK CASCADE로 users·chat_logs·관련 토큰 즉시 삭제(구현됨, `admin_user_deleted` 감사 이벤트 기록).
- **백업 내 파기**: 순환 교체로 최대 7세대 내 자연 소멸. 즉시 파기 요청 시 백업 전체 재생성으로 대응(운영 판단 기록 남김).
- **파기의 한계(정직하게 문서화)**: stderr 로그에 대화 원문이 없어야 함 — 로그 샘플 주기 감사(분기 1회) 필요.

## 4. 열람 통제

- 본인: `/api/me/chats`만. 타인 기록은 401/404로 차단(테스트 `test_verified_gaps`).
- 관리자: `grants` 테이블에 명시 부여된 계정만. 열람 시 `admin_logs_viewed` 이벤트(누가/무엇을/몇 건/사유) 기록 — **사유 필드는 2026-09-11 패치로 추가**.
- 관리자 계정은 최소 유지(원칙 1~2개)하고, 부여/회수를 `manage_admin.py` 감사 기록과 함께 운영.

## 5. 이동권·처리 거부

- **내보내기**: 본인 대화 JSON 내보내기 스크립트(백로그 0.5일) — 이동권 최소 대응.
- **관리자 열람 제외 요청**: 현 구조에서는 미지원. 요청 시 계정 삭제로만 대응 가능 — 가입 고지에 이 한계를 포함해 투명하게.
